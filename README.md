# Zoi Observer

inZOI를 관찰 위주로 플레이할 수 있도록 돕는 자율 관리 모드입니다. 현재 버전은 **0.6.17 실험판**입니다.

[0.6.17 설치 ZIP](downloads/ZoiObserver-v0.6.17.zip) · [설치 및 사용설명서](사용설명서.md) · [개발 방향·구현 범위·검증 계획](개발계획.md)

## 설치

1. 게임을 종료하고 기존 모드 폴더와 `saved` 안의 진단을 백업합니다. ZIP의 `ZoiObserver_XDX478` 폴더를 Windows 문서 폴더의 `inZOI/Mods/InGame` 아래에 복사하고 기존 `saved` 폴더를 보존합니다.
2. 게임에서 가구를 불러온 뒤 관찰창에서 **Start**를 누릅니다. **Played**는 플레이 이력이 있는 가구를 관리합니다.
3. 도시 간 휴가를 자동으로 진행할 때는 게임 화면에서 **다른 작업 모드**를 끕니다.

## 0.6.1

- **"지금" 진단** (`why.js`): 조이가 왜 지금 아무 요청도 받지 않는지를 한 줄로 보여 준다. 기능마다 흩어진 대기 시각 20종, 작업 재시도 시각, 목표 막힘, 비켜 선 소망, 초대 대기를 한곳에서 읽어 "대기 n건 · 가장 먼저 풀림: 무엇 몇 시 (이유)"로 표시한다. 동작은 바꾸지 않는 읽기 전용이다. 진단 파일의 `why`에 조이별 전체 대기 목록이 남는다.

## 0.6.0

- **끊긴 목표 이어가기**: 출근·근무, 급한 욕구, 이동 때문에 끊긴 소망·야망 행동은 실패로 세지 않고(재시도 지연·막힘 기록 없음) 여유가 생기면 같은 행동을 다시 요청한다. 같은 행동은 하루 3번까지만 이어가고 그 뒤로는 일반 실패로 처리한다.
- **선행 조건 연쇄와 정체 처리**: 목표 → 필요 → 준비 → 재시도 → 완료 확인의 단계를 목록으로 기록한다. 준비 단계에서 증거 없이 오래 머문 소망은 4게임시간 동안 비켜서 다른 소망이 먼저 진행되고(만료가 가까우면 더 빨리), 야망은 비키지 않고 막힌 기록을 지운 뒤 필요 조건을 처음부터 다시 찾는다(2게임일 기준).
- **무인 운영 기록**: 가구 단위로 팝업 수, 모드가 처리한 수와 사람이 닫은 수, 팝업이 게임을 막은 시간, Stop·선택 변경 같은 수동 개입, 같은 결제가 두 번 나간 경우를 날짜별로 센다. 관찰창에 "무인 운영 n/7일 · 개입 · 팝업 자동 · 중복 결제" 줄이 나오고 7일 기준 충족 여부를 표시한다.
- **가족 조율** (`family.js`): 가족 둘이 같은 물건으로 동시에 보내지지 않게 하고, 오늘 소망을 덜 깬 가족이 소망 차례를 먼저 받으며, 초대·파티는 한 집에서 한 명만 주최한다.
- 수동 개입 집계는 근사치다. 모드가 누르지 않은 팝업 종료, Stop, 모드가 바꾸지 않은 선택 변경을 개입으로 본다.

## 0.5.9

- **현장 점검** (`fieldcheck.js`): 게임 없이는 알 수 없던 것들을 모드가 게임에서 처음 실행될 때 스스로 조사한다. 한 번에 읽기 전용 질문 하나씩(행동 검색 11종, 명령 정보 11종, 응답 형태 4종), 게임 상태는 바꾸지 않는다. 초대·파티·퇴사·은퇴·창업·영업 시작으로 분류된 실제 행동 이름과 분류되지 않은 후보, 선택 전환·관계·방문자·행사 명령의 사용 가능 여부가 진단 파일(`saved/observer-report.cfg`의 `fieldCheck`)에 남는다. 관찰창 상태줄에 진행도와 결과 요약이 표시된다.
- 진단 파일에 가족 순환 선택 상태(`rotation`)도 함께 기록한다.

## 0.5.8

보지 않아도 가족 전원이 관리되도록 보강했다.

- 원래부터 가족 전원을 차례로 살피고 이동·대화·욕구·취업 등 대부분의 명령은 선택 여부와 무관하게 보낸다. 다만 게임이 **선택된 조이에게만** 허용하는 일(개인 자율 행동 켜기, 냥스토어·포켓마켓 같은 휴대폰 화면 작업, 처음 가 본 장소의 주변 물건 확인)이 있어 선택되지 않은 가족은 그 부분이 밀렸다.
- **가족 순환 선택** (`rotation.js`): 선택되지 않은 가족이 위 작업을 기다리면 선택을 그 조이로 자동 전환한다(긴급 욕구 우선, 오래 기다린 순, 전환 간격 최소 90게임분, 여행·팝업·휴대폰 작업 중에는 안 함). 전환이 게임에 반영됐는지 확인하고 두 번 연속 실패하면 하루 쉰다. 관찰창 버튼으로 끌 수 있다.
- **장소 기억**: 한 번 확인한 장소(집 등)의 물건 목록을 20분(실시간) 기억해, 선택된 조이가 다른 곳에 있어도 나머지 가족이 그 장소의 물건으로 소망·야망·수리·작업을 이어간다. 실행 전 게임에 가능 여부를 다시 확인한다.
- 0.5.7 자동 리뷰 지적 3건 반영: 이전 저장을 불러오면 미래의 은퇴 기록을 지움, 컴퓨터가 닿지 않을 때는 창업·퇴사를 포기하지 않고 대기, 영업 시작 행동은 계산대·간판류부터 찾음.
- 순환 선택은 휴대폰 답장에서 이미 쓰던 선택 전환 명령을 쓰지만, 이 용도로는 아직 실제 게임에서 확인하지 못했다.

## 0.5.7

조이마다 다른 삶을 살도록 진로와 일과를 개인화했다.

- **삶의 방향** (`career-path.js`): 기질·특성과 야망으로 조이마다 직장인 / 창업 지향 / 자유직 중 하나의 길을 정하고(14게임일 유지, 야망이 바뀌면 재검토), 나이·저축·재직 기간에 따라 다음 단계를 고른다. 구직 → 재직 → 재직하며 창업 준비 → 창업 → 사업이 자리 잡으면 퇴사 → 노년 은퇴 → 은퇴 후 창업·소일거리·휴식.
- **개체 고유 성향**: 같은 기질이라도 조이마다 고정된 대담함 수치가 달라 창업 시기, 필요한 종잣돈, 노후 자금 기준, 비슷한 일자리 중 취향이 다르다. 안정형 직장인도 대담한 개체는 중년에 가게를 차릴 수 있다.
- **직업 선택에 야망 반영**: 현재 야망 미션이 요구하는 기술을 쓰는 일자리에 가산점을 준다.
- **일과 개성** (`persona.js`): 대화, 초대·파티, 행사, 외출, 휴가, 소망, 야망, 직장, 개인 작업, 집 정돈, 집 꾸미기의 우선순위를 조이별로 다르게 둔다. 욕구·긴급 작업은 그대로다. 관찰창에 "성향"과 "삶의 방향"이 표시된다.
- 자유직과 1인 사업은 집 컴퓨터의 제작·출판 행동으로 생활비가 부족하지 않아도 꾸준히 일한다.
- **확인된 것과 아닌 것**: 취업·이직(`career.join`)만 게임에서 확인된 명령이다. 퇴사·은퇴, 사업장 창업, 영업 시작은 게임이 제공하는 행동에서 찾아 요청하고 게임 데이터(직업 기록 소멸, 사업장 보유, 영업 중)로만 성공을 인정한다. 찾지 못하면 직장을 유지하거나 1인 사업으로 전환한다. 모의 검사로만 확인했다.

## 0.5.6

- 초대·파티 보완(자동 리뷰 지적 5건 반영): 이미 집에 와 있는 지인은 초대 대상에서 빼서 "원래 있던 손님"을 초대 성공으로 잘못 배우지 않는다. 한 번 성공했던 행동도 두 번 연속 불발하면 쉰다. 눈앞 행동이 쉬는 중이면 휴대폰 경로를 찾아본다. 다른 플레이 가구에 사는 친구도 초대 대상이 된다. 손님 대기·방문 중에는 행사·휴가 출발도 하지 않는다.

## 0.5.5

- **지인 초대·파티** (`gathering.js`): 집에 있고 욕구·일정에 여유가 있는 조이가, 우정 50 이상 또는 애정 40 이상인 가족 밖 지인을 집으로 부른다. 가까운 지인이 둘 이상이면 파티 행동을 먼저 고른다(파티는 3게임일에 한 번, 초대는 하루 한 번, 10~20시).
- 어떤 행동이 초대·파티인지는 미리 정해 두지 않고 게임이 제공하는 행동 목록과 행동 검색에서 찾는다. 요청 뒤 4게임시간 안에 **손님이 실제로 집에 와 있는지**로만 성공을 판정하고, 두 번 연속 아무도 오지 않은 행동은 3게임일 동안 쓰지 않는다. 성공한 행동은 가족이 함께 기억한다.
- 손님을 기다리거나 맞이하는 동안에는 여가·사교 외출을 하지 않고, 손님이 오면 바로 대화를 시작한다.
- **아직 게임에서 확인하지 못한 부분**: 실제 초대·파티 행동 ID와 휴대폰 초대 경로. 모의 검사 9개로만 확인했다.

## 0.5.4

개발계획 2단계(목표 계획기)의 첫 부분과 자동 검토 지적 2건입니다. **모의 검사만 통과했습니다.**

- **야망은 끝까지**: 기술 준비의 3게임일 제한과 연습 회차 제한을 야망에는 적용하지 않습니다.
- **연습 한도는 실행 기준**: 시작하지 못한 연습 요청은 하루 한도를 쓰지 않습니다. 한도는 소망 3회, 야망 5회.
- **요청 집계 누락 수정**: 행동 요청을 만든 순간 성적표에 기록합니다.
- **돌봄 중복 요청 수정**: 돌봄이 보호자의 대기열에 남아 있으면 예약을 유지합니다(게임 시간 120분 한도).
- 야망의 기간 제한 해제 두 곳은 조건식만 바꿨고, 그 경로를 직접 지나는 모의 검사는 아직 없습니다. 연습 한도와 나머지는 검사 95개에 포함됩니다.
- 2단계의 나머지(여러 선행 조건 연결, 중단·재개 기록, 소망 고정핀)는 [개발계획](개발계획.md)의 설계를 따르며, 실제 게임 연결 뒤에 진행합니다.

## 0.5.3

개발계획 1단계인 **성적표**입니다. **모의 검사만 통과했고 실제 게임에서는 아직 확인하지 않았습니다.**

- **사건 단위 기록** (`scoreboard.js`): 조이별·게임일별로 소망 완료, 사라진 소망, 야망 미션 완료, 행동 요청, 실패와 막힌 이유, 외출과 현장 성공, 근무·수면·자유·위험 욕구 시간, 욕구 최저치, 실제 관찰 간격을 기록합니다.
- **완료는 게임 미션 기록으로만** 셉니다. 사건마다 고유 키가 있어 다시 읽거나 저장을 불러와도 중복되지 않습니다. 목록에서 사라졌지만 완료 기록이 없는 소망은 “확인 못 한 종료”로 따로 셉니다.
- **추가 호출 최소화**: 미션 기록은 소망 목록이 바뀌었을 때와 게임 시간 1시간마다만 읽습니다.
- 관찰창에 **오늘 소망 n/5**와 미달 사유를 표시하고, Report에 `score`를 추가했습니다. 기존 `daily`는 비교를 위해 남겨 두었습니다.
- PR 자동 검토에서 지적된 관계 기록 문제를 고쳤습니다. 관찰 사이에 끝난 대화도 관계 수치 변화가 측정되면 그 결과를 남깁니다.
- 자동 검토 2차 지적 반영: 이미 센 사실의 표시를 원본 기록에 직접 남겨, 기록이 많아져도 같은 실패·막힘을 다시 세지 않습니다. 이전 저장을 불러왔을 때는 그 시점 이후에 한 납부·답장 기록을 복원하지 않습니다(그 시간선에서는 아직 안 낸 고지서이므로). 여행 귀환처럼 게임 시간이 이어지는 경우에는 기존대로 복원합니다.
- 아직 없는 지표: 사용자 개입 횟수, 팝업 처리율과 정지 시간, 결제 중복, 가족 간 대기·돌봄 부담.

## 0.5.2

0.5.1을 기준본으로 정리한 안정화 버전입니다. **모의 검사만 통과했고, 이번 수정 내용을 실제 게임에서 다시 확인하지는 않았습니다.**

- **소망 외출 오류 수정**: 시설 태그나 장소 단서로 후보를 찾은 뒤 선언되지 않은 값을 읽어 실행 오류가 났고, 이동 요청까지 가지 못했습니다. 해당 조건은 바로 앞 조건과 겹쳐 의미가 없었으므로 제거했습니다.
- **설치본과 소스 일치**: 0.5.1 설치 ZIP의 `travel.js`는 소스보다 이전 상태였습니다(출발 직전 준비 상태 재확인 누락). 0.5.2 ZIP은 검사를 통과한 소스에서 그대로 만듭니다.
- **검사 80개**(0.5.4에서 95개, 0.5.5에서 104개, 0.5.6에서 109개, 0.5.7에서 128개, 0.5.8에서 133개, 0.5.9에서 138개, 0.6.0에서 151개, 0.6.1에서 157개): 소망 외출의 연속 흐름(집에서 불가 → 시설 선택 → 이동 → 도착 후 행동 → 미션 확인 → 귀가), 출발 직전 준비 만료·계획 변경, 그리고 이전 검사 묶음(`observer.test.cjs`)을 현재 모듈에 다시 연결했습니다.
- **미선언 변수 검사**: 같은 종류의 오류를 올릴 때마다 잡도록 `eslint.config.mjs`와 CI 단계를 추가했습니다.

0.4.7~0.5.1은 이 저장소 밖에서 개발되어, 전달받은 0.5.1 소스를 한 번에 가져왔습니다. 그 사이의 변경 내용은 [사용설명서](사용설명서.md)의 버전별 기록에 있습니다. `downloads/ZoiObserver-v0.5.1.zip`은 전달받은 그대로 보관한 파일이며 위 두 문제가 들어 있으므로 설치에는 0.5.2를 사용하세요.

다음 단계는 [개발계획](개발계획.md)의 순서(성적표 → 목표 계획기 → 가족 조율 → 갱신형 지도 → 일과표 → 인생 방향)를 따릅니다.

## 0.4.6

목표를 정하고, 준비하고, 실패를 해결해 끝까지 수행하는 연결을 보강했습니다. **이번 버전은 모의 검사만 통과했고 Windows 실게임 검증은 아직 하지 않았습니다.**

- **작업 관리 통합**: 조이별 할 일(휴대폰·집 관리·소망·야망·택배·행사·청소·외출·대화·진로 등)을 한 목록에서 중요도, 기다린 시간, 소망·행사 기한, 소요시간으로 순서를 정합니다. 앞선 작업이 계속 생겨도 뒤의 작업이 오래 밀리지 않습니다. 작업별로 밀린 횟수와 마지막 시도를 기록해 정상 대기와 계속 밀리는 문제를 구별합니다.
- **실패 원인별 대안**: 수면, 다른 조이가 사용 중, 경로 막힘(두 번 시작되지 않은 대상), 기술 부족, 물건·시설 없음, 게임 거부를 구분합니다. 원인마다 기다리는 시간과 다음 행동이 다릅니다. 사용 중인 물건은 피하고, 도달하지 못한 대상은 잠시 제외합니다.
- **소망 준비 과정 연결**: 목표 → 필요 조건 → 준비 → 원래 목표 재시도 → 완료 확인 흐름을 기록하고 표시합니다. 원래 행동이 기술 부족으로 비활성이면 그 기술을 연습하고, 실제 성장이 확인되면 원래 행동을 다시 시도합니다.
- **연애·관계 연결 수정**: 결혼·연인·새 관계 소망이 대화 처리로 간 뒤 맞는 행동을 찾지 못하던 누락을 고쳤습니다. 관계 단계에 맞는 구애 행동을 고르고, 아직 이르면 친분 대화로 이어 갑니다. 선택한 조이는 반경 30m의 최대 6명을 확인합니다. 선택하지 않은 조이도 같은 장소의 관리 대상과 기억한 상대를 찾습니다. 상대별로 결과(호감 상승·변화 없음·거절·미실행·수면)와 다음 만남 시점을 기억하고, 반응이 나쁘면 시간을 두고 다른 인연을 찾습니다. 기억한 상대가 공공장소에 있으면 다시 만나러 가고, 새 인연이 필요하면 사람이 있는 장소로 갑니다.
- **저장·여행 후 복구**: Start 상태와 처리한 납부·답장을 모드 설정 파일에도 기록합니다. 여행 귀환이나 저장 불러오기로 자동 관리가 꺼진 상태가 되면 같은 가구일 때 다시 켜고, 이미 처리한 납부·답장은 다시 하지 않습니다. Stop을 누른 상태는 유지합니다. 도시 전환 중 일시적 오류는 자동 관리를 끄지 않고 잠시 쉬었다가 다시 확인합니다.
- **관찰창**: “처리 중” 대신 지금 하는 일, 막힌 이유, 다음 차례, 오래 밀린 작업, 상대별 관계 상황을 표시합니다. 사업·이사·입양은 **판단 후보**로만 표시합니다.
- **진단**: Report에 게임일별 소망 완료·대기·준비·반복 실패·밀린 작업·미처리 답장 수를 남겨 7게임일 비교에 씁니다.

## 0.4.5

- 게임의 기술 경험치와 레벨을 따로 읽습니다. 그림 소망에 맞는 행동과 이젤이 모두 없으면 조건이 맞는 집에서 이젤 배치를 검토합니다.
- 일반 답장과 납부 모두 처리 요청을 저장해 늦은 응답이 중복 발송으로 이어지지 않게 합니다. 실제 공과금·이자 선택지와 금액 문구에 맞춰 판단합니다.
- Windows 실게임에서 여행 안내 여섯 개 선택, 1인 여행 결제 70미유, 도원 도착, 체크인과 숙박 후 차하야 복귀를 확인했습니다. 이 시험은 예약 UI를 직접 구동했고 귀환은 게임이 처리했습니다. 모드의 일정 선택부터 이어지는 전 과정, 복귀 후 자동 관리 재개, 가족 동행, 실게임 납부는 검증이 남아 있습니다.

## 0.4.4

- 목표별 준비 단계·다음 행동·실제 기술 성장·최근 실패를 게임 저장 상태에 보존합니다. 일부 `SkillLevel` 소망에 손재주 연습 후보를 추가했습니다. 짧은 연습에 레벨 변화가 없다는 이유만으로 실패나 완료라고 단정하지 않습니다.
- 대기 명령과 진행 중 생활 행동을 존중하고, 생활 판단과 팝업 감시의 실행을 직렬화합니다. 같은 행동·대상의 반복 실패에는 대기 시간을 둡니다.
- 납부 금액과 스크립트를 확인하고, 동일 고지의 결과 미확인 요청을 반복하지 않습니다. 여행도 요청 결과가 늦으면 예약을 유지한 채 관찰을 재개합니다.
- 도시 도착 후 잔액 차이·동반인의 현재 도시를 따로 기록합니다. 실제 납부 거래·현지 체크인은 별도 확인 대상입니다.
- 소망 고정핀, 미관과 동선을 판단하는 자동 인테리어, 일반 선행 조건을 전부 해결하는 기능은 후속 개발 범위입니다.

## 검사와 패키징

외부 패키지 설치 없이 Node.js와 Python 3으로 실행합니다.

```sh
node --test tests/*.test.cjs
python3 scripts/package.py
python3 scripts/check.py
```

미선언 변수 검사는 선택 사항이며 네트워크가 필요합니다.

```sh
npx --yes eslint@9 ZoiObserver_XDX478/ui/HouseholdObserver
```

모의 검사는 실제 게임의 API 호환성과 행동 결과 검증을 대신하지 않습니다. GitHub에 올릴 때도 같은 검사를 실행하도록 CI를 추가했습니다.
